# REQUIREMENTS — Deskling

요구사항 ID는 테스트 이름과 `docs/ACCEPTANCE.md`에서 참조한다.
우선순위: **S** = 첫 vertical slice 필수, **M** = MVP 필수, **L** = 이후.

## 기능 요구사항 (FR)

### 창 (Window)

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-W1 | 창은 투명 배경이고 OS 프레임(타이틀바·테두리·그림자)이 없다. | S |
| FR-W2 | 창은 기본적으로 바탕화면에 박혀(다른 창 아래) 있고, 사용자가 "위에 띄우기"로 바꿀 수 있다(ADR-021). | S |
| FR-W3 | 장면의 빈 영역을 드래그하면 창이 이동한다. 캐릭터·컨트롤 클릭은 드래그로 처리되지 않는다. | M |
| FR-W4 | 사용자가 크기를 S/M/L 프리셋으로 바꿀 수 있고, 창 크기와 장면 크기가 함께 바뀐다. | M |
| FR-W5 | 사용자가 장면 투명도를 30%~100% 사이로 조절할 수 있다. | M |
| FR-W6 | 크기·투명도·항상 위·모션 설정은 앱을 다시 열어도 유지된다. 설정 외의 데이터는 저장하지 않는다. | M |
| FR-W7 | 컨트롤은 마우스를 올리거나 키보드 포커스가 들어올 때만 보인다. | M |
| FR-W8 | 사용자가 앱을 닫을 수 있는 컨트롤이 있다. | M |

### 장면과 상태 (Scene)

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-S1 | 장면은 헤르메스의 아이소메트릭 픽셀 미니룸(FR-R1)과 그 안의 헤르메스로 구성된다. (원래 어두운 작업실 → ADR-019로 대체) | S |
| FR-S2 | 11개 시각 상태(`offline`, `idle`, `thinking`, `coding`, `browsing`, `terminal`, `file-work`, `waiting-approval`, `delegated`, `success`, `error`)를 지원한다. | S(6개)/M(11개) |
| FR-S3 | 각 상태는 서로 다른 **헤르메스의 행동**, **아이콘**, **모니터 화면**, **텍스트**를 가진다. 색상만으로 구분하지 않는다. | S |
| FR-S4 | 현재 상태 텍스트는 보조기술에 `role="status"`로 알려진다. | S |
| FR-S5 | 승인 대기는 호박색, 오류는 붉은 주황색 강조를 쓴다. | M |
| FR-S6 | 모니터 화면 내용은 상태를 암시하는 추상 도형이며 실제 코드·명령·URL·파일명을 표시하지 않는다. | S |

### 활동 패널 (Panel)

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-P1 | 캐릭터를 클릭하거나 키보드로 활성화하면 최근 활동 패널이 열린다. | M |
| FR-P2 | 패널은 최근 이벤트를 최신순으로 최대 12개, 시각과 고정 문구로 보여준다. | M |
| FR-P3 | 패널은 닫기 버튼과 Esc 키로 닫힌다. | M |
| FR-P4 | 패널 문구는 이벤트 종류와 도구 카테고리에서만 만든다. 이벤트의 자유 텍스트를 표시하지 않는다. | M |

### 이벤트 (Events)

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-E1 | 모든 이벤트는 provider 중립 `AgentEvent` v1 규격(`docs/EVENT_PROTOCOL.md`)을 따른다. | S |
| FR-E2 | 모든 원시 입력은 정규화 함수를 통과해야 리듀서에 도달한다. 실패한 입력은 버린다. | S |
| FR-E3 | 정규화 결과에는 규격에 정의된 필드만 존재한다. 알 수 없는 필드는 복사하지 않는다. | S |
| FR-E4 | 리듀서는 순수 함수이며 같은 이벤트 열에 대해 항상 같은 상태를 만든다. | S |
| FR-E5 | 같은 세션에서 `seq`가 이전 이벤트 이하인 이벤트는 무시한다. | S |
| FR-E6 | 시각 상태는 이벤트로 알려진 사실에서만 도출하며 시간 경과로 상태를 바꾸지 않는다. | S |

### 데모 (Demo)

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-D1 | 데모 소스는 고정된 스크립트를 고정된 간격으로 재생한다(결정적). | S |
| FR-D2 | `core` 스크립트는 `idle → thinking → coding → terminal → success → idle`을 재생한다. | S |
| FR-D3 | `tour` 스크립트는 11개 상태를 모두 순서대로 재생한다. | M |
| FR-D4 | 데모 스크립트는 끝나면 처음부터 반복한다. | S |
| FR-D5 | 데모 모드에서는 모든 상태와 패널 열림 여부에 관계없이 `DEMO` 배지가 보인다. | S |
| FR-D6 | 데모 이벤트도 실제 이벤트와 같은 정규화 경로를 지난다. | S |

### 모션 (Motion)

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-M1 | 시스템의 "동작 줄이기" 설정을 따른다. | S |
| FR-M2 | 사용자가 앱 안에서 모션을 `시스템 / 줄이기 / 전체`로 바꿀 수 있다. | M |
| FR-M3 | 모션이 줄어든 상태에서도 포즈·아이콘·텍스트로 상태를 구분할 수 있다. | S |

### 생활감 (Vitals & Room) — ADR-016, ADR-017

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-V1 | `usage.reported`(v2)의 토큰·컨텍스트 숫자를 검증해 받아들이고, 그 외 내용은 버린다. | M |
| FR-V2 | 에너지 = 사용자 예산 대비 남은 토큰. 4단계(full/ok/low/empty)와 보고 없음(unknown)을 구분한다. | M |
| FR-V3 | 화남 = 컨텍스트 채움 비율. 4단계(calm/annoyed/angry/furious)와 unknown을 구분한다. | M |
| FR-V4 | 장면은 숫자 없이 분위기로만 표현한다: 에너지는 책상 위 빈 캔 수·배터리 이모트·걷는 속도, 화남은 땀·핏줄·김 이모트. 색만으로 구분하지 않는다. | M |
| FR-V5 | 활동 패널에 남은 토큰/예산, 컨텍스트 사용량/한도와 비율을 숫자로 보여준다. 보고가 없으면 "보고 없음". | M |
| FR-V6 | 사용자가 토큰 예산을 50k/100k/200k/500k/1M 중에서 고를 수 있고 설정으로 저장된다. | M |
| FR-V7 | 오프라인이면 불이 꺼진 방에서 침대에 누워 자고, 작업 상태는 책상, 대기 중에는 일상(FR-R3). 활동 패널을 여는 버튼이 헤르메스를 따라다닌다. | M |
| FR-V8 | 위치가 바뀌면 걸어간다(reduced-motion이면 즉시). FR-R6과 같다. | M |

### 키우기 (Growth & Care) — ADR-018

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-G1 | 경험치는 수용된 `turn.succeeded` 수다. 앱을 다시 켜도 유지된다. | M |
| FR-G2 | 경험치에 따라 헤르메스가 아기 → 어린이 → 어른으로 자란다(크기·별 배지). | M |
| FR-G3 | 경험치에 따라 방 소품이 하나씩 생긴다(포스터, 책상 화분, 줄 조명, 러그, 책, 트로피). | M |
| FR-G4 | 사용자가 쓰다듬기·간식으로 애정도를 올릴 수 있고, 장면에 하트·간식 반응이 보인다. 에이전트와 실제 지표에는 영향이 없다. | M |
| FR-G5 | 사용자가 이름을 지을 수 있다(최대 12자). 이름은 패널에만 보인다. | M |
| FR-G6 | 데모와 실제 에이전트는 성장 프로필이 따로이며, 데모 프로필은 DEMO로 표시된다. | M |

### 미니룸과 일상 (Room Life) — ADR-019, ADR-020, ADR-021

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-R1 | 장면은 밝은 아이소메트릭 픽셀 미니룸이다(침대, 컴퓨터 책상, 샤워 부스, 냉장고, 식탁, TV, 소파, 책장, 문). 원본 그림만 쓴다. | M |
| FR-R2 | 작업 상태에서는 헤르메스가 컴퓨터 책상에 앉아 있고, 상태마다 동작·이모트·모니터 화면이 다르다. | M |
| FR-R3 | 대기 중에는 헤르메스가 스스로 돌아다니며 일상(샤워, 밥, TV, 책, 창밖, 스트레칭, 물주기, 낮잠)을 한다. 대기 중에는 컴퓨터를 쓰지 않는다. | M |
| FR-R4 | 친구가 문으로 들어와 함께 놀다 나간다. 대기 중 가끔 스스로, 또는 패널의 "친구 초대"로. 위임 중에는 친구가 도우미로 옆에서 일한다. | M |
| FR-R5 | 오프라인이면 방 불이 꺼지고 침대에서 잔다. 승인 대기면 방 앞으로 나와 손을 흔든다. | M |
| FR-R6 | 이동은 걸어서 하며, reduced-motion이면 순간 이동한다. 일상 선택은 시드 고정이라 테스트에서 재현된다. | M |
| FR-R7 | 창은 기본적으로 바탕화면에 박혀(다른 창 아래) 있고, Dock에 나타나지 않는다. "위에 띄우기"로 바꿀 수 있다. | M |

## 보안 요구사항 (SEC)

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| SEC-1 | chain-of-thought·숨겨진 reasoning을 표시하거나 저장하지 않는다. | S |
| SEC-2 | 프롬프트 전문, 파일 내용, 파일 경로, 터미널 명령어, 환경변수, API 키, Authorization 헤더, raw tool arguments를 UI·로그·저장소에 남기지 않는다. | S |
| SEC-3 | 검증 실패 로그에는 에러 코드만 남기고 입력값을 포함하지 않는다. | S |
| SEC-4 | 앱은 에이전트에게 명령을 보내거나 승인을 대신하는 기능이 없다. | S |
| SEC-5 | Tauri capability는 필요한 창 권한만 허용한다(드래그, 항상 위, 항상 아래, 크기, 닫기). 셸·파일시스템 플러그인을 쓰지 않는다. | S |
| SEC-6 | Provider 전용 로직은 adapter 레이어에만 있고 UI 컴포넌트에는 없다(린트로 강제). | S |
| SEC-7 | localStorage에는 UI 설정(`deskling.settings.v1`)과 펫 프로필(`deskling.pet.v1`: 숫자와 사용자 이름)만 저장한다(ADR-018). | M |
