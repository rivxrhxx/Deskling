# REQUIREMENTS — Deskling

요구사항 ID는 테스트 이름과 `docs/ACCEPTANCE.md`에서 참조한다.
우선순위: **S** = 첫 vertical slice 필수, **M** = MVP 필수, **L** = 이후.

## 기능 요구사항 (FR)

### 창 (Window)

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-W1 | 창은 투명 배경이고 OS 프레임(타이틀바·테두리·그림자)이 없다. | S |
| FR-W2 | 창은 기본적으로 바탕화면에 박혀(다른 창 아래) 있고, 사용자가 "위에 띄우기"로 바꿀 수 있다(ADR-021). | S |
| FR-W3 | 장면의 빈 영역을 드래그하면 창이 이동한다. 요약 말풍선·컨트롤 클릭은 드래그로 처리되지 않는다. | M |
| FR-W4 | 사용자가 크기를 S/M/L 프리셋으로 바꿀 수 있고, 창 크기와 장면 크기가 함께 바뀐다. | M |
| FR-W5 | 사용자가 장면 투명도를 30%~100% 사이로 조절할 수 있다. | M |
| FR-W6 | 크기·투명도·위에 띄우기·모션·토큰 예산·보기·데모 시나리오 설정은 앱을 다시 열어도 유지된다. 설정과 사무실 경험치(SEC-7) 외의 데이터는 저장하지 않는다. | M |
| FR-W7 | 컨트롤은 마우스를 올리거나 키보드 포커스가 들어올 때만 보인다. | M |
| FR-W8 | 사용자가 앱을 닫을 수 있는 컨트롤이 있다. | M |

### 장면과 상태 (Scene)

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-S1 | 장면은 아이소메트릭 픽셀 사무실(FR-R1)과 그 안의 직원들(세션마다 한 명, FR-MS1)로 구성된다. (어두운 작업실 → ADR-019 미니룸 → ADR-025 사무실로 대체) | S |
| FR-S2 | 11개 시각 상태(`offline`, `idle`, `thinking`, `coding`, `browsing`, `terminal`, `file-work`, `waiting-approval`, `delegated`, `success`, `error`)를 지원한다. | S(6개)/M(11개) |
| FR-S3 | 각 상태는 서로 다른 **직원의 행동**, **아이콘**, **모니터 화면**, **텍스트**를 가진다. 색상만으로 구분하지 않는다. | S |
| FR-S4 | 사무실 요약 문구(FR-S7)는 보조기술에 `aria-live="polite"`로 알려진다. (원래 헤르메스 상태의 `role="status"` → ADR-025 §5로 대체) | S |
| FR-S5 | 승인 대기는 호박색, 오류는 붉은 주황색 강조를 쓴다(직원 상태·알림 줄·요약 말풍선 모두). | M |
| FR-S6 | 모니터 화면 내용은 상태를 암시하는 추상 도형이며 실제 코드·명령·URL·파일명을 표시하지 않는다. | S |
| FR-S7 | 장면 위 **사무실 요약 말풍선**은 고정 문구로 센다: "N명 일하는 중", "N명 승인 대기", "N명 오류", "N명 쉬는 중"(이 순서, 0인 항목 생략, " · "로 연결), 아무도 없으면 "아무도 없음". 톤·아이콘: 승인 대기가 있으면 호박색(손), 아니면 오류가 있으면 붉은 주황(경고), 아니면 일하는 사람이 있으면 기본(괄호), 모두 쉬면 민트(컵), 없으면 dim(플러그). 대기·성공은 쉬는 중으로 센다(ADR-025 §5). | M |

### 활동 패널 (Panel)

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-P1 | 사무실 요약 말풍선(`<button aria-haspopup="dialog" aria-expanded>`)을 클릭하거나 키보드로 활성화하면 활동 패널이 열리고, 다시 누르면 닫힌다. (원래 캐릭터 클릭 → ADR-025 §5로 대체) | M |
| FR-P2 | 패널은 최근 이벤트를 최신순으로 최대 12개, 시각과 고정 문구로 보여준다. | M |
| FR-P3 | 패널은 닫기 버튼과 Esc 키로 닫히고, 닫히면 포커스가 요약 말풍선으로 돌아간다. | M |
| FR-P4 | 패널 문구는 이벤트 종류와 도구 카테고리에서만 만든다. 이벤트의 자유 텍스트를 표시하지 않는다. | M |
| FR-P5 | 패널 구성(ADR-025): "사무실" 묶음(경험치 N, 해금한 소품 수 "소품 n/6", 다음 해금 "다음: 줄 조명 · 7" 또는 "모두 해금", 데모면 DEMO), 사무실에 있는 세션 목록(FR-MS6)과 토큰 예산 선택(FR-V6), 세션 이름이 붙은 최근 활동, 보기 자동/실제/데모(FR-CC4), 데모일 때 시나리오 선택. 펫 카드·헤르메스 지표 묶음은 없다. | M |

### 생활감 (Vitals) — ADR-016, ADR-025 §6

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-V1 | `usage.reported`(v2)의 토큰·컨텍스트 숫자를 검증해 받아들이고, 그 외 내용은 버린다. | M |
| FR-V2 | 에너지 = 사용자 예산 대비 남은 토큰. 4단계(full/ok/low/empty)와 보고 없음(unknown)을 구분한다. | M |
| FR-V3 | 화남 = 컨텍스트 채움 비율. 4단계(calm/annoyed/angry/furious)와 unknown을 구분한다. | M |
| FR-V4 | 에너지·화남은 **직원마다 따로** 그 세션의 보고에서만 읽는다. 장면은 숫자 없이 분위기로만 표현한다: 에너지는 자기 책상 위 빈 캔 수·배터리 이모트, 화남은 머리 위 땀·핏줄·김 이모트. 보고가 없으면 표시 없음. 색만으로 구분하지 않는다. (원래 헤르메스 하나의 지표 → ADR-025 §6으로 대체) | M |
| FR-V5 | 활동 패널의 세션 줄마다, 보고된 것만 고정 형식 숫자로 보여준다: "남은 80k · 컨텍스트 70%"(토큰만이면 "남은 80k", 컨텍스트만이면 "컨텍스트 70%"). 보고가 없으면 숫자 없음. (원래 헤르메스의 남은 토큰/예산·컨텍스트 묶음 → ADR-025 §6으로 대체) | M |
| FR-V6 | 사용자가 토큰 예산을 50k/100k/200k/500k/1M 중에서 고를 수 있고 설정으로 저장된다. 모든 직원의 에너지를 같은 예산으로 읽는다. | M |
| FR-V7 | ~~오프라인이면 침대에서 자고 … 패널 버튼이 헤르메스를 따라다닌다.~~ **대체됨(ADR-025):** 아무도 없으면 사무실 불이 꺼지고(FR-R5), 작업은 책상, 대기는 라운지(FR-R3). 패널은 요약 말풍선이 연다(FR-P1). 캐릭터 위 버튼은 없다. | M |
| FR-V8 | 위치가 바뀌면 걸어간다(reduced-motion이면 즉시). FR-R6과 같다. | M |

### 사무실 (Office) — ADR-025 (ADR-019·ADR-020 대체), ADR-021

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-R1 | 장면은 밝은 아이소메트릭 픽셀 **사무실**이다: 책상 8개(모니터·의자), 회의 테이블, 커피머신, 정수기, 라운지 소파, 책장, 화이트보드, 창문, 화분, 문. 원본 그림만 쓴다. (원래 침실 미니룸 → ADR-025 §2로 대체) | M |
| FR-R2 | 작업 상태(생각·코딩·웹·터미널·파일)의 직원은 자기 책상에서 일하고 모니터에 상태 화면이 보인다. 승인 대기 → 일어나 손 흔들기, 오류 → 머리 감싸기, 성공 → 3초 환호. | M |
| FR-R3 | 대기 중인 직원은 라운지(커피머신·정수기·소파·창가·화분 중 빈 자리, 시드 고정 선택)로 걸어가 쉬고, 일이 시작되면 책상으로 돌아온다. 위치만 바뀌고 잡담은 만들지 않는다. (원래 헤르메스의 일상 → ADR-025 §3으로 대체) | M |
| FR-R4 | 위임 중인 직원의 책상 옆에 작은 도우미 봇이 있다. 무작위 손님과 "친구 초대"는 없다. 사람은 모두 실제 세션이다(FR-MS*). | M |
| FR-R5 | `agent.offline`인 직원은 문으로 나간다. 아무도 없으면 사무실 불이 꺼진다. (원래 침대에서 잠 → ADR-025 §3으로 대체) | M |
| FR-R6 | 이동은 가구를 피하는 격자 경로(A*)로 걸어서 하며, reduced-motion이면 순간 이동한다. 라운지 자리 선택은 시드 고정이라 테스트에서 재현된다. | M |
| FR-R7 | 창은 기본적으로 바탕화면에 박혀(다른 창 아래) 있고, Dock에 나타나지 않는다. "위에 띄우기"로 바꿀 수 있다. | M |

### 세션마다 직원 한 명 (Multi-session) — ADR-025 (ADR-022 대체), ADR-023

| ID | 요구사항 | 우선 |
| --- | --- | --- |
| FR-MS1 | 모든 세션(종류 무관)이 직원 한 명이다. 집주인은 없다. 이름은 종류 안의 번호: Claude n, Codex n, Hermes n, 데모 n, 에이전트 n(custom). 모습은 `source.kind`로 고른다. (원래 집주인 헤르메스 + 친구 → ADR-025 §1로 대체) | M |
| FR-MS2 | 직원은 세션의 첫 이벤트로 문으로 들어와 비어 있는 가장 작은 번호 책상(8개)에 앉고, `agent.offline`이면 문으로 나간다. 9번째부터는 패널에만 "(자리 없음)"으로 보인다. | M |
| FR-MS3 | 직원은 자기 세션의 사실만 보인다(FR-R2·FR-R3). 한 직원의 상태가 다른 직원을 움직이지 않는다. | M |
| FR-MS4 | 세션별 커서·사실·사용량. 한 세션의 이벤트가 다른 세션을 바꾸지 않는다. 끝난 세션 커서 64개 기억. | M |
| FR-MS5 | `session.message`: 둘 다 사무실에 있으면 4초간 서로 돌아보며 말풍선 이모트("…"), 상대를 모르거나 없으면 보낸 쪽 위에 편지 이모트 3초. 내용은 없다. | M |
| FR-MS6 | 패널: 사무실에 있는 세션 목록(이름 + 상태 + 톤 점 + 보고된 숫자, FR-V5)과 세션 이름이 붙은 최근 활동. 누군가 승인 대기·오류면 요약 말풍선 아래 알림 줄이 그 직원을 이름으로 알린다("Claude 2 · 승인 대기 중" + 나머지 수). | M |
| FR-MS7 | 기본 데모 시나리오 "사무실 하루"(`office`, 예전 `friends` 설정은 이리로 옮김): Claude 3 + Codex 2 + 에이전트 1이 차례로 들어와 일하고(생각·코딩·웹·터미널·파일), 쉬러 라운지에 갔다 돌아오고, 대화·편지, 승인 요청과 처리, 오류, 위임(도우미 봇), 성공(환호) 뒤 한 명씩 나간다. 한 박자 ≥ 3초, 한 바퀴 80~100초. DEMO 배지. | M |

### Claude Code 연결 — ADR-024

| ID | 요구사항 | 우선 |
